## 2. Inputs and conclusion

### Actual Statements

For any field `K` of characteristic zero, define `matrixLieAlgebra K` to be
the Lie subalgebra of `Matrix (Fin 27) (Fin 27) K` generated by the pinned
six raising and six lowering matrices, cast entrywise from integers.
Define `d5MatrixLieAlgebra K` using the five retained nodes `[5,4,3,1,2]`.
Neither definition mentions the generated candidate basis or its dimension.

[MatrixLieAlgebra](../../../../../Math/LieGroups/E6/Minuscule/MatrixLieAlgebra.lean) proves:

- `matrixLieAlgebra_span` and `d5MatrixLieAlgebra_span`: the proposed finite
  linear spans equal those actual generated Lie subalgebras.
- `matrixBasis_linearIndependent` and `d5MatrixBasis_linearIndependent`:
  the proposed vectors are linearly independent over `K`.
- `matrixLieAlgebra_finrank`: the first subalgebra's underlying submodule
  has finrank **78**.
- `d5MatrixLieAlgebra_finrank`: the retained subalgebra has finrank **45**.
- `d5MatrixLieAlgebra_le` and `d5MatrixInclusion_injective`: the actual
  matrix Lie inclusion is constructed and injective.

The audits instantiate these statements over both `Rational` and `Complex`.
The Cartan matrices in the basis have bracket provenance `[E_i,F_i]`;
they are not silently added as independent generators.

## 4. Proof structure

### Soundness and Trust

The proof has four layers, each checked by the Lean kernel.

1. [SparseMatrixCertificate](../../../../../Math/LieAlgebras/SparseMatrixCertificate.lean)
   interprets finite integer entry lists as ordinary matrices. It proves
   insertion/normalization correctness, multiplication and bracket semantics,
   and soundness of successful equality checks. Lists are certificate syntax,
   not a replacement mathematical matrix model. Coordinate functionals with
   nonzero integer diagonal pairings prove linear independence after scalar
   extension to a characteristic-zero field.
2. [GeneratedLieSpan](../../../../../Math/LieAlgebras/GeneratedLieSpan.lean)
   proves the Lie-theoretic step independently of matrices and E6: containing
   generators and being stable under their brackets suffices for containment
   of their generated Lie span. Jacobi handles iterated brackets. Conversely,
   strict well-founded bracket provenance puts every proposed vector inside
   that generated algebra. These two containments give equality.
3. [MatrixLieCertificate](../../../../../Math/LieAlgebras/MatrixLieCertificate.lean)
   combines the sound checks, provenance induction, span equality, and
   linear independence into a reusable finite-dimension theorem.
4. [LieCertificateChecks](../../../../../Math/LieGroups/E6/Minuscule/LieCertificateChecks.lean)
   checks the concrete integer data, including equality to the **actual
   pinned generators**, 123 provenance records, 936/450 generator-bracket
   equations, and 78-by-78 / 45-by-45 dual pairing tables. All finite proofs
   use `decide +kernel`, not `native_decide` or an external computation axiom.

The external Python emitter supplies only
[data](../../../../../Math/LieGroups/E6/Minuscule/LieCertificateData.lean): sparse matrices,
bracket ancestry, integer closure coefficients, and scaled dual functionals.
The data module is tracked, so a clone can run the normal Lean build without
Python or the temporary JSON. Generating wrong data does not create a theorem;
the corresponding Lean check fails. The external program emits no proof terms.
Fresh regeneration was byte-for-byte equal to the tracked 33,034-byte module.

### Controls

The [E6 audit](../../../../../Math/LieGroups/E6/Audit/AuditMatrixLieAlgebra.lean) checks concrete
rational/complex dimensions and the inclusion map. Negative controls reject
a nonzero matrix equated with zero, circular bracket ancestry even on zero
matrices, a reversed sl2 bracket, and a vanished diagonal dual pairing.
Duplicate entries are explicitly allowed when they evaluate to the same matrix.

The [generic audit](../../../../../Math/LieAlgebras/Audit/AuditMatrixLieCertificate.lean)
constructs a separate three-dimensional sl2 example and enforces an import
boundary excluding TauCeti and the checked gauge-family module prefixes.
The external arithmetic/emitter suite passes ten tests; those tests are
engineering checks, not part of the formal trust boundary.

## 6. Scope and limitations

### Still Open

The [E6-0d comparison](E6_GECK_COMPARISON.md) identifies both generated
matrix Lie algebras with the actual scalar-extended E6/D5 Geck carriers.
The retained D5 algebra has not been identified with the Lie algebra of
the repository's compact Spin(10) group. The earlier external eigenlabel
enumeration is not used as a trusted root-space proof.

In particular, equal dimensions of two algebras, together with maps from a
Serre presentation, do not prove equality of the maps' kernels. The
Serre-to-Geck surjection alone does not establish descent of the 27.
E6-0d instead uses matching Cartan bases, a proper-product argument,
simplicity, and checked dimensions to construct a faithful Geck action.

The [compact-carrier acceptance contract](../GUT/E6_MATRIX_PROTOTYPE.md#compact-carrier-acceptance-contract)
remains in force: compact real-form identification, global form/center,
actual continuous Spin inclusion, oriented 27 branching, and the positive
physical-model inhabitant are not supplied by this milestone. No new
E6 selection-rule endpoint or physical assumption is introduced.
