# Frozen First-Phase Plan

## 1. Extract consequences before choosing parameters

Produce a short constraint register with one row per used theorem:
application hypotheses, prohibition predicate, derived necessary condition,
SM requirements, bridge obligations, and exact strength of the output.
Inspect the existing theorem signatures before choosing new API names.

Initial consequences to inspect:

- Scalar/cyclic route: on a nontrivial actual quotient carrier with certified
  scalar action, prohibition requires detection/nonzero cyclic charge.
- Full qque constituent route: under its source semisimplicity and full-field
  hypotheses, qque prohibition is equivalent to absence of a shared constituent
  between Sym² Q and the specified U/E product. This is a qque constraint,
  not sufficient all-B1 protection.
- Surplus route: B1 prohibition rules out a common irreducible whose source
  Hom multiplicity exceeds target Hom multiplicity in every participating
  species, under the admitted mass-independent presentations.
- Standard-chain control: a requested pure charge target with nonzero qque
  charge is inconsistent with the admitted commuting action/index class.

Distinguish a theorem-derived necessary condition from the hypotheses of
one sufficient proof route. Failure of applicability is not a required
physical escape condition unless a theorem proves that claim.

## 2. Pull back predicates without claiming an inverse function

For parameters x, let A(x) denote application prerequisites, S(x) the explicit
SM constraints, P(x) the requested prohibition, and N(x) a necessary condition.
The core certificate must prove A(x) ∧ P(x) → N(x). The survivor predicate is
S(x) ∧ N(x) within the admitted domain; it does not prove P(x) or model existence.
If A(x) is undecided, retain it visibly rather than discarding x.

Reuse ordinary predicate preimages and existing selection APIs where possible.
Do not create a redundant completeness theorem or new model bundle merely
for wrapper convenience. Generic algebra belongs in Math, actual mass/species
connections in Physics, and fixed unified-model regressions in GUT.

## 3. Symbolic and finite inputs

Start with symbolic charge and multiplicity constraints, preserving free
parameters where the theorem permits them. A finite interface is optional:
for a genuinely finite parameter type and decidable certified conditions,
prove that filtering preserves every admitted protected input and rejects
only inputs contradicting proved necessary conditions.

Do not assume that a finite list of representations makes masses, VEVs or
couplings finite. Any finite control must state its exact bounds and provide
all applicability certificates separately from its numeric tables. If only
the conditional preimage is feasible, that is a valid first-phase endpoint.
No exhaustive input domain or UV enumeration is claimed.

For the scalar/cyclic control, test both a neutral nontrivial domain and a
zero-domain exception. Prefer existing CyclicCharge character-line witnesses;
mark them as formal controls, not physical SM operator spaces. For the surplus
control, reuse the existing unequal-copy and disjoint-constituent regressions.
Do not count a trivial finite truth-table filter as new physical progress.

## 4. Treat SM consistency as explicit constraints

Separate structural SM requirements (embedding, field representations and
requested light index) from full phenomenological viability. A requested IR
spectrum is a condition to realize, not an already proved radical identity.
Index agreement alone does not establish exact fields. A condition inconsistent
with the explicit SM constraints is a useful exclusion result.

The first phase may represent SM constraints as an explicitly named predicate
when no reusable structural bridge is available. Such a predicate must not be
presented as a verified SM-consistency decision procedure. Keep unexplored
scalar/VEV/action choices symbolic and distinguish them from missing evidence.
No anomaly, RGE, hadronic, cosmological or rate requirements are silently added.

## 5. Acceptance and stopping conditions

Complete the first phase when the two named routes yield audited conditional
necessary-condition/preimage certificates and meaningful controls, with a
register showing exactly which physical premises remain supplied. A scoped
feasibility result identifying a concrete missing theorem is also acceptable.

Stop before new continuous branching foundations, general noncommuting-action
classification, antilinear/CP foundations, or construction of protecting UV
models. Do not recursively replace a blocked route with unrelated research.
Do not report survivors as protecting models or qque vanishing as all-B1
prohibition. Preserve derivative/EOM/IBP and generated-interaction boundaries.

Proof milestones require focused builds, persistent strict transitive axiom
audits, layout checks, one serialized full lake build, docs links and diff
checks, plus assumption review. No sorry, custom axioms, audit exceptions,
new dependencies, remote push or master merge. Documentation-only milestones
require links/diff checks and explicitly state that Lean was not rebuilt.
